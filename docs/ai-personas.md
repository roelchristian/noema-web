# AI personas (Phase 1)

Seven immutable built-ins ship at version 1: `oxford_don`, `conyo`, `editor`, `tutor`, `antiquarian`, `socratic`, `salon_wit`. Shared presentation metadata lives in `src/shared/ai-personas.ts`; instructions live only in the server registry. Identity contains ID, version, and `builtin`/`custom` origin. Custom management, conversations, and workspace generation remain deferred; future request variants must explicitly opt into the policy allowlist.

`GenerationRequest` admits persona selection only on `sourcePage`, `explanation` (blocks or reading passages), and `review`. Writing Review changes explanatory rationale only; corrections retain the author's voice. Existing source-page formats, revisions, and critique evidence rules remain authoritative. The `editorial` variant is **source preprocessing**, so it remains excluded. There is no other prose-writing request kind in the current application.

All summaries (manual and background), titles/language utilities, metadata enrichment/classification, entity discovery/scanning/extraction/linking, embeddings/indexing, OCR/source and math preprocessing, and connection/diagnostic requests retain their provider payloads. Generic transport does not inject persona instructions. Golden provider payloads change only for the four eligible fixtures (including both explanation forms). Models, admission, limits, lazy prompt construction, streaming, and parsers retain their existing policy.

The policy snapshots identity and composes trusted task instructions, persona, then overriding task/output/evidence/language/security restrictions. The final precedence rules explicitly subordinate style without duplicating the task prompt. Cultural register never selects an output language. Humour and whimsy are muted for sensitive content, and invented anecdotes are forbidden. Deterministic composition tests cannot establish actual model compliance.

The global default is `oxford_don`, stored in SQLite `intelligence_preferences`, independent of vaults and credentials. Unsupported saved IDs safely fall back; unsupported preference writes fail validation. Request overrides do not write the default. Persona-only updates do not increment model preference cancellation state or abort enrichment/embedding requests.

Settings → AI → AI Persona shows read-only names, descriptions and illustrative samples. Source-page forms, revisions, and reading explanations use a discreet inline Persona name with an optional request override. Inherited defaults are labelled; descriptions and samples remain in Settings. The compact control retains keyboard support and a 44px mobile target. Block AI actions include an Explanation persona submenu, applied to the next explanation request only. Source revisions inherit the draft's stored ID/version unless explicitly overridden; block regeneration similarly retains the group's identity. New source-page and reading-explanation metadata store persona identity rather than copies of persona instructions. Existing task snapshots remain compatible. Persona instructions do not enter generated source/user document content.

Generation metadata parsing preserves absent legacy identities and historical removed/custom IDs without silently relabelling them. Pages and saved reading notes retain identity on acceptance, editing, restart, and vault backup restoration; block groups also carry identity through validation and backup remapping. New generation with an unavailable identity/version falls back to Oxford Don v1.

## Verification

- `npm run build` includes style ownership and client/server/test typechecks.
- `npm run test:all` includes consolidated `test/ai-personas.test.mjs`, unchanged utility payload contracts, request/admission/streaming regressions, legacy metadata, revision identity, saved notes, backup round trips, and unrelated menu/link/editor tests.
- `PLAYWRIGHT_MODULE=/opt/codex/cua_node/lib/node_modules/playwright-core/index.mjs node --import tsx scripts/check-personas-browser.mjs` runs the real built app and HTTP backend at desktop/mobile widths against disposable SQLite and deterministic provider responses. Set `PLAYWRIGHT_MODULE`/`CHROMIUM_PATH` for other installations and `NOEMA_SCREENSHOTS` for the evidence destination. It never connects to a live provider.
- `test/fixtures/persona-style-evaluation.json` supplies the same mathematical, evidence, French-language and sensitive-content prompts across all personas and a human scoring rubric. Human/live stylistic differentiation evaluation is **UNRUN**. No live provider credentials, user vaults, or external API spend were used.
