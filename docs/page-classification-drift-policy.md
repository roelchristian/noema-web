# Page classification drift policy (v1)

Classification baselines are captured only after a successful provider classification. Local assessments advance `lastAssessedContentHash`, never `classifiedContentHash` or the baseline. A changed body hash alone is not proof of stale subjects. Manual assignments always win, including while a provider request is running.

Normalisation ignores styling, block IDs, whitespace and generated explanation blocks. Entity references use their displayed mention text or resolved name. Mathematical symbols and Unicode text remain available. A bounded baseline stores up to 24,002 sampled characters (start, middle and end), 128 headings and 4,096 distinct token counts. It is derived metadata inside the existing vault lifecycle and backup system, never routine diagnostic log content. Embeddings are optional, limited to 4,096 dimensions and reused only when their model, dimensions and content fingerprints match.

A multiset content change ratio of 30% is a provisional candidate signal. Two distinct disciplinary terms identify stronger local subject evidence; ambiguous words such as “field”, “group” and “order” are excluded. New subject evidence or headings can request classification even when a long page has cosine similarity of 1.0. Same-discipline expansion and paraphrase normally retain the existing assignment. Near-identical cached semantic evidence (cosine at least 0.97) retains assignments absent strong novel subject evidence. A cosine below 0.92 plus substantive local change can request classification. No embedding API is called by this gate. Large changes lacking reliable disciplinary evidence conservatively request review.

This is hysteresis at the request boundary: small edits cannot repeatedly switch plausible assignments. The local score never writes a category; only a validated provider result or explicit user choice writes assignments. A taxonomy version change first checks canonical IDs locally. Legacy metadata with unknown provenance receives no invented classification baseline.

The initial vocabulary is intentionally small and English-oriented. Unicode content is preserved, but multilingual subject evidence and non-sampled sections can require further calibration. Keep recall and false-negative drift detection visible alongside avoided calls. The labelled corpus in `test/fixtures/page-drift-corpus.json` covers mathematics, computing, historical notes, theology, language and interdisciplinary additions. Expand it with consented real notes before tuning thresholds.

Regression tests were added but are intentionally not executed in this task because the user requested skipping testing and validation. No empirical accuracy, timing or before/after token benchmark is claimed. A reproducible benchmark should replay the corpus and writing sessions, report true positives / (true positives + false negatives), stable edits incorrectly reclassified, provider calls avoided, input/cached/output tokens and cost per successfully enriched page. Compare identical snapshots, provider profiles and policy versions.

## Before/after replay report

Status: prepared, intentionally not executed under the request to skip validation. `node --import tsx scripts/benchmark-page-drift.mjs` prints a deterministic JSON report comparing legacy changed-hash classification decisions with v1 local decisions over the checked-in corpus. It includes requests avoided, recall, false positives and false negatives, with case identifiers and compact reason codes. No measured results are supplied until that command is explicitly run. The replay estimates classification decisions only; actual token, latency and cost savings require instrumented provider sessions.

Current indexed page passages can supply semantic evidence without a provider call. All passage vectors must be present, current for the saved page revision, joined on each indexing content hash and configured model/dimensions, and the page cannot be awaiting reindexing. The supplied page title and canonical body hash must match the persisted page. A token-weighted page aggregate is captured at successful classification and compared only with the same aggregate model policy. Legacy whole-note embeddings are not assumed equivalent to classification body fingerprints.


## Enrichment scheduling and field ownership

The unified coordinator selects `title`, `domains`, `language` and `summary` independently. It shares eligible fields in one structured provider call. Metadata uses a separately persisted model profile, defaulting to the inexpensive configured Luna profile with reasoning disabled. Existing explanation settings do not silently change the enrichment model. The legacy utility endpoint is a compatibility facade over this coordinator.

SQLite jobs coalesce by page, survive restarts, and revalidate page revision, body fingerprint, editing lock, vault availability and field ownership at dispatch and commit. Initial work waits about 12 seconds; later classification waits 40 seconds; summary work normally waits 25 seconds. The browser title compatibility scheduler waits 10 seconds for initial titles. Saves supersede pending snapshots. Actual classifications impose a 30 minute cooldown; deferred domain work remains queued. Provider failures retry at most three times with increasing delays, while credentials, invalid structured responses and permanent failures wait for a later action. Background cancellation reaches the provider AbortSignal.

Titles are stored as derived metadata and shown on untitled pages until an authored save accepts them. Manual titles, domains and languages remain protected. Automatic summaries are enabled by default, with existing explicit vault preferences preserved through backups. Deleting a summary suppresses automatic recreation. Explicit regeneration can restore a deleted summary. Summary assessments use their own generating baseline: punctuation and small corrections retain freshness, while approximately 10 percent cumulative word change, changed headings or changed title can require regeneration. A combined title and summary result uses the effective final title for freshness. Language inference caches undetermined results and reconsiders inferred languages after a significant change in script distribution or vocabulary composition.

Long inputs explicitly use representative excerpts and changed passages; classification metadata records sampling coverage. Activity metrics separate local decisions with no requested fields from actual provider calls, and retain provider input, cached input, output, reasoning tokens and latency. Cost remains unknown until versioned per-model prices are configured through `/api/intelligence/pricing`. These provisional thresholds and qualitative heuristics still require calibration on consented real writing sessions; no measured accuracy or savings are claimed here.
